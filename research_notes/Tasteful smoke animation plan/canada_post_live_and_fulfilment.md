## 1. Is the Canada Post REST/XML web service still the interface in 2026? Auth, environments, limits, terms, format, Workers

### Takeaway
There are now TWO Canada Post developer platforms. The old Developer Program (XML over REST or SOAP, API key as HTTP Basic, soa-gw.canadapost.ca) still runs but Canada Post staff call it "deprecated" with no shutdown date; the new Developer Portal (JSON only, OAuth 2.0 client-credentials Bearer token, api.canadapost-postescanada.ca) is where all eight APIs now live and where all new APIs will launch. A new build should target the new portal, which also removes the need for XML parsing in a Worker.

### Cited Findings (all read 2026-11-14)
- New Developer Portal release notes, dated April 30, 2026, all "Supported": Rating 4.0.0, Shipping 8.0.0, Tracking 2.0.0, Post Office Services 1.0.0, Pickup 1.0.0, Returns 2.0.0, Service Information 2.0.0, Customer Information Services 2.0.0. REST only; "XML is no longer supported"; "SOAP is no longer supported"; "Every API request must now include a valid OAuth 2.0 Bearer access token in the authorization header."; Merchant Registration endpoint decommissioned. [F] - [Release notes](https://developer-developpeur.canadapost-postescanada.ca/devportal-portaildesdeveloppeurs/release-notes)
- Portal API list also includes AddressComplete 1.0.0. Shipping 8.0.0 contains the manifest operations (no separate manifest API). [F] - [Rating overview](https://developer-developpeur.canadapost-postescanada.ca/devportal-portaildesdeveloppeurs/api/overview/rating)
- Shipping 8.0.0 operations: Create Shipment, Get Shipment, Get Shipment Price, Get Shipment Details, Get Shipment Public Key Info, Get Shipment Receipt, Get Shipments, Get Groups, Get Artifact (label, reprintable), Void Shipment, Request Shipment Refund; manifest side: Transmit Shipments, Get Manifest, Get Manifest Details, Get Manifests, Get Artifact (manifest). Serves "enterprise and small business customers"; contract shipping is enterprise only. [F] - [Shipping overview](https://developer-developpeur.canadapost-postescanada.ca/devportal-portaildesdeveloppeurs/api/overview/shipping)
- Auth on the new portal: POST `https://<APIGateway>/oauth2/token`, `grant_type=client_credentials`, client id and secret as form fields, scope `merchant`; response has `expires_in` (examples 3600 and 28800 seconds) and `consented_on`; an expired token returns 401. [F] - [Authentication guide](https://developer-developpeur.canadapost-postescanada.ca/devportal-portaildesdeveloppeurs/authentication-guide)
- New portal host shown in docs: `api.canadapost-postescanada.ca`, sample path `/prod/devportal-portaildesdeveloppeurs/shipping/v1/`. Headers: `Authorization: Bearer`, `Content-Type` (POST), `Accept` (GET), optional `Accept-Language` en-CA/fr-CA; `*/*` returns an error. Errors are JSON `{messages:[{code, description}]}`. Path parameters `{mailed by customer}` and `{mobo}` are your customer number. [F] - [API fundamentals](https://developer-developpeur.canadapost-postescanada.ca/devportal-portaildesdeveloppeurs/api-fundamentals)
- Environments on the new portal are app types, not hostnames: an app is Test or Production and cannot be changed later. Test apps "use static/stubbed data and don't trigger billing"; production apps bill the customer number tied to the API key. API Secret "will only be displayed once". A Canada Post business profile (customer number) is required. [F] - [Developer guide](https://developer-developpeur.canadapost-postescanada.ca/devportal-portaildesdeveloppeurs/developer-guide)
- New portal rate limits: numbers are NOT published. Rolling 60-second window per product; test limits may be lower; when exceeded the response reads "Server Rejected by SLM Monitor"; guidance is at least 250 ms between calls and a 60-second wait after the error; increases by email to developer.program@canadapost.postescanada.ca. Per-app usage against the limit is visible in the portal dashboard. [F] - [API throttling and rate limits](https://developer-developpeur.canadapost-postescanada.ca/devportal-portaildesdeveloppeurs/rate-limits), [FAQ](https://developer-developpeur.canadapost-postescanada.ca/devportal-portaildesdeveloppeurs/frequently-asked-questions)
- Legacy program published limits (per API key, per minute, default / upgraded): Group A Create Shipment, Create NC Shipment 646 / 1076; Group D Get Rates, Discover Services 840 / 1399; Group E Tracking Summary/Details 20 / 500; Group C Transmit Shipments, Get Manifest 730 / 1095; Group K Pickup price/create/cancel 180 / 200; Group B Void/Refund 468 / 702. Blocked until the 60-second window expires. [F] - [API Throttle Limits (legacy)](https://www.canadapost-postescanada.ca/info/mc/business/productsservices/developers/throttlelimits.jsf)
- Legacy program still documented and live: dev `https://ct.soa-gw.canadapost.ca`, prod `https://soa-gw.canadapost.ca`, `Authorization: Basic base64(userid:password)`, XML bodies with versioned media types (for rating `application/vnd.cpc.ship.rate-v4+xml`); wrong-environment key returns 403 AA002; key/customer mismatch 403 AA003. No deprecation banner on the legacy pages themselves. [F] - [REST fundamentals (legacy)](https://www.canadapost-postescanada.ca/info/mc/business/productsservices/developers/services/fundamentals.jsf), [Get Rates (legacy)](https://www.canadapost-postescanada.ca/info/mc/business/productsservices/developers/services/rating/getrates/default.jsf)
- Canada Post staff (cpc.admin, "Developer Program team"), forum reply July 31, 2026: the legacy Developer Program supports REST and SOAP with XML; the new portal is REST and JSON; the legacy program "has been deprecated"; customers may still enrol and get legacy credentials for now by calling the Technical Support Desk 1-877-376-1212 for identity verification. No retirement date given. [F] - [Is SOAP API deprecated?](https://forum.developer-developpeur.canadapost-postescanada.ca/t/is-soap-api-deprecated/78)
- Staff post June 5, 2026: "we encourage all developers to transition to our latest RESTful services." [F] - [About the Legacy APIs](https://forum.developer-developpeur.canadapost-postescanada.ca/t/about-the-legacy-apis-a-propos-des-api-heritees/61)
- Canada Post: "All new Canada Post APIs will launch exclusively on this portal." Existing users can still manage legacy keys; migration contact developer.program@canadapost.postescanada.ca; no deadline listed. [F] - [Developer Portal blog](https://www.canadapost-postescanada.ca/blogs/business/ecommerce/canada-post-developer-portal-faster-scalable-and-built-for-business-growth/), [Integrate with our APIs](https://www.canadapost-postescanada.ca/cpc/en/business/ecommerce/integrate-apis.page)
- Legacy key risk seen in the wild: Sept 17, 2026 a years-old production key began returning "E002 AAA Authentication Failure"; staff said the system changed so the key password can only be viewed by regenerating it, and regeneration invalidates the old one. [F] - [Forum thread](https://forum.developer-developpeur.canadapost-postescanada.ca/t/developer-program-production-api-key-stopped-working-suddenly-today/95)
- Third-party plugins (WooCommerce, BigCommerce) still require legacy credentials and users report they cannot find them in the new portal. [F, forum topic list] - [(Legacy) Developer Program APIs category](https://forum.developer-developpeur.canadapost-postescanada.ca/c/test-category/14)
- Terms (Developer Portal Agreement, "Last Updated Dec 2025"): licence is only "to create, maintain and use software applications to interface with Canada Posts web services"; must not "damage, disable, overburden or impair the Program"; Canada Post "may track the usage rates of the applications you create"; personal and confidential information must be stored on systems in Canada (or NATO country) and "destroyed immediately following the use for which it was obtained"; "Canada Post does not warrant that your use of the Program will be uninterrupted or error free"; services may be removed "for indefinite periods of time without notice"; suspension "at any time in Canada Post's sole discretion". The agreement does not address caching of rates or showing Canada Post rates beside other carriers. [F] - [Developer Portal Agreement](https://www.canadapost-postescanada.ca/cpc/en/support/kb/company-policies/terms-conditions/developer-portal-terms-and-conditions.page)
- Cloudflare Workers limits relevant to an outbound rate call: subrequests per invocation 50 (Free) / 10,000 (Paid); CPU time 10 ms (Free) / 30 s default (Paid), network wait does not count; "There is no set time limit on individual subrequests"; 6 simultaneous connections waiting on headers; `ctx.waitUntil()` up to 30 s after the response. No default outbound fetch timeout is stated. [F] - [Workers limits](https://developers.cloudflare.com/workers/platform/limits/)

### Inferences
- Build against the new portal (JSON + OAuth). A Worker then needs only `fetch` and `JSON.parse`; no XML library. Cache the Bearer token (KV or in-memory with expiry from `expires_in`) so each checkout costs one subrequest, not two.
- Because Workers set no time limit on a subrequest, the store must impose its own (abort the rate call after a few seconds and fall back to the local table). Canada Post publishes no timeout guidance.
- Rate caching is not prohibited by the agreement text read, but rates are priced "for the current system date" and fuel changes weekly, so any cache should be short (minutes, keyed on origin, destination postal code, weight, dimensions, options) and never span a fuel-surcharge change.
- The data-residency clause (personal information on systems in Canada) matters for D1: confirm the D1 location hint is a Canadian or acceptable region before storing addresses obtained through the program.
- Legacy remains a possible fallback path (its limits are generous: 840 rate calls/min), but it is deprecated and needs a phone call to obtain keys; do not build new work on it.

### Gaps
- New-portal per-product rate limit numbers: COULD NOT VERIFY (not published). Confirm in the app dashboard after registering, or by email to the developer program.
- New-portal JSON field names and exact endpoint paths for Rating 4.0.0 and Shipping 8.0.0: the API reference sits behind sign-in. Confirm by registering a Test app and downloading the YAML/OpenAPI files.
- Sandbox token/gateway hostname for Test apps: not stated in public pages.
- Legacy retirement date: none published. Confirm by email to developer.program@canadapost.postescanada.ca.
- `AbortSignal.timeout` support in Workers: not on the limits page read. Confirm in Cloudflare's fetch/runtime API docs.

## 2. What a Solutions for Small Business (SfSB) customer gets versus a contract customer

### Takeaway
An SfSB shop gets its discounted rates from the rating call by sending its customer number and NO contract id, pays for each label by the default credit card saved in its canadapost.ca profile, and needs no manifest. Contract customers send a contract id, pay on account, and must transmit a manifest.

### Cited Findings (all read 2026-11-14)
- Get Rates (legacy doc; the new API claims "complete feature parity"): `customer-number` gives discounted commercial or SfSB rates; omit it for counter (consumer) rates; `contract-id` "must be omitted for Solutions for Small Business members"; `quote-type` `commercial` (default) or `counter`. [F] - [Get Rates](https://www.canadapost-postescanada.ca/info/mc/business/productsservices/developers/services/rating/getrates/default.jsf)
- Non-Contract Shipping is the legacy service "For Canada Post general business or VentureOne customers": Create Non-Contract Shipment is "Used to generate and pay for a shipping label, including validation and payment authorization"; "No manifests are required." Calls: Create, Get Artifact (label PDF), Get Receipt, Get Details, Get Public Key Info (QR code/public URL), Get Shipments, Get Shipment, Request Refund (only if not sent and no scan events). [F] - [Non-Contract Shipping](https://www.canadapost-postescanada.ca/info/mc/business/productsservices/developers/services/onestepshipping/default.jsf)
- Legacy endpoint `POST https://soa-gw.canadapost.ca/rs/{mailed by customer}/ncshipment`, media type `application/vnd.cpc.ncshipment-v4+xml`; response gives `shipment-id`, `tracking-pin`, and links for label, receipt, details, refund, publicLabel. [F] - [Create Non-Contract Shipment](https://www.canadapost-postescanada.ca/info/mc/business/productsservices/developers/services/onestepshipping/createshipment.jsf)
- Staff answer for a VentureOne (small business) account on the shipment API, July 6, 2026: set `intended-method-of-payment` to `CreditCard`, not `Account`, because small business accounts have no line of credit; a credit card must be saved and set as default in the canadapost.ca profile and charges go to that card. [F] - [Forum thread](https://forum.developer-developpeur.canadapost-postescanada.ca/t/shipment-api-please-select-a-different-method-of-payment-error-for-venture-one-small-business-account/68)
- Contract Create Shipment doc: `intended-method-of-payment` is CreditCard (saved and defaulted on the profile), Account (requires a contract), or SupplierAccount. Non-contract customers using this service must send `transmit-shipment` = true: the shipment is transmitted and billed immediately, needs no manifest, and cannot be voided. Without that flag, Transmit Shipments then Get Manifest is required or "manual billing at full rates and/or loss of the automation discount". [F] - [Create Shipment (contract)](https://www.canadapost-postescanada.ca/info/mc/business/productsservices/developers/services/shippingmanifest/createshipment.jsf)
- New portal "Ship parcels" guide: commercial customers have a contract number and are billed to a credit account; "Small Business customers" use their small business account number; flow is Get Rates (optional) then Create Shipment then Get Artifact, with Transmit Shipments/manifest "required for commercial and manifest-based flows". [F] - [Ship parcels](https://developer-developpeur.canadapost-postescanada.ca/devportal-portaildesdeveloppeurs/ship-parcels)
- Label output: `output-format` `8.5x11` or `4x6`; `encoding` `PDF` (default) or `ZPL` (4x6 only, error 9191 otherwise). ZPL needs a printer that can truncate text; Citizen and older-firmware Zebra printers cannot, so use PDF there. [F] - [Create Shipment (contract)](https://www.canadapost-postescanada.ca/info/mc/business/productsservices/developers/services/shippingmanifest/createshipment.jsf), [Printing labels](https://developer-developpeur.canadapost-postescanada.ca/devportal-portaildesdeveloppeurs/printing-labels)
- Third-party confirmation: ShipStation API docs say Canada Post Small Business accounts "have no manifest requirement and receive an error if they try to manifest"; EasyPost says "Retail customers don't need to manifest", contract customers must. [F] - [ShipStation Canada Post guide](https://docs.shipstation.com/apis/docs/carriers/canadapost-guide.md), [EasyPost Canada Post BYOCA guide](https://docs.easypost.com/carriers/canada-post-byoa-guide)
- Through Dec 31, 2026 SfSB members "automatically receive the program's best available shipping discounts, regardless of shipping volume" (already in docs/SHIPPING.md). [F there] - [Canada Post news release 2026-09-21](https://www.canadapost-postescanada.ca/cpc/en/our-company/news-and-media/corporate-news/news-release/2026-09-21-canada-post-introduces-new-pricing-discounts-market-insights-and-ecommerce-solutions-to-support-canadian-businesses)

### Inferences
- The store's label call is: Create Shipment with payment method CreditCard, no contract id, no manifest step. Operational dependency: a valid default credit card on the Canada Post profile. An expired card stops label printing, so the admin screen should surface the API's payment error plainly.
- The rate shown at checkout and the amount later charged for the label come from the same customer number, so they should match provided weight, dimensions and options are identical and the label is bought before a fuel or price change. Persist the quoted service, options, weight and box on the order and reuse them for the label call; show staff the difference if the re-price differs.
- SfSB discount level after Dec 31, 2026 may drop back to volume-based tiers; the live rate call absorbs that automatically, the local fallback table would not.

### Gaps
- Whether the new JSON Shipping 8.0.0 keeps a separate non-contract endpoint or a single Create Shipment with a payment flag for small business: COULD NOT VERIFY from public pages. Confirm in the signed-in API reference with a Test app.
- Whether the SfSB "best discount" continues after Dec 31, 2026: not announced in sources read.

## 3. Exactly what Get Rates returns, and how to request options (coverage, signature, proof of age, card for pickup, dangerous goods)

### Takeaway
One call returns, per service: base price, each option's price, each adjustment (fuel surcharge as FUELSC with its percent), taxes, a final "due" total, the cubed (volumetric) weight, and an expected delivery date. Options are sent as option codes; there is no dangerous-goods or limited-quantity field anywhere in the API, so the cologne rule must be enforced by the store (restrict to DOM.RP and DOM.EP service codes).

### Cited Findings (all read 2026-11-14)
- Request: `origin-postal-code` and destination `postal-code` (ANANAN uppercase), `parcel-characteristics` weight in kg (99.999), optional dimensions in cm (999.9), flags `unpackaged`, `mailing-tube`, `oversized` (oversized set automatically when dimensions are sent); `services/service-code` limits which services are rated (DOM.RP Regular, DOM.EP Expedited, DOM.XP Xpresspost, DOM.PC Priority); `expected-mailing-date` affects delivery estimate only, "rates use the current system date"; optional `promo-code`. [F] - [Get Rates](https://www.canadapost-postescanada.ca/info/mc/business/productsservices/developers/services/rating/getrates/default.jsf)
- Response per `price-quote`: `service-code`, `service-name`; `price-details` with `base` (pre-tax), `taxes` (gst/pst/hst with percent), `due` (total including options, surcharges, discounts, taxes), `options` (code, name, price), `adjustments` (code, name, cost, percent). Adjustment codes: FUELSC fuel surcharge, AUTDISC automation discount, PROMODISC, PLATFMDISC, NEWREGDISC, SAADJ service area adjustment. `weight-details` includes `cubed-weight`. `service-standard`: `am-delivery`, `guaranteed-delivery`, `expected-transit-time`, `expected-delivery-date`. [F] - same page
- Option codes valid on rating: SO (signature), COV (coverage, needs `option-amount`), COD, PA18, PA19, HFP (card for pickup), DNS (do not safe drop), LAD (leave at door). Shipping adds D2PO (deliver to post office; needs a notification email). [F] - same page; [Create Non-Contract Shipment](https://www.canadapost-postescanada.ca/info/mc/business/productsservices/developers/services/onestepshipping/createshipment.jsf)
- New portal option list (camelCase `optionCode`, `optionAmount`): SO, COV, COD, DC (delivery confirmation), PA18, PA19, PA21, HFP, DNS, LAD, D2PO. Packaging flags `mailingTube`, `unpackaged`, `oversized` in `parcelCharacteristics`; only one of the unpackaged/oversize surcharges applies. [F] - [Ship parcels](https://developer-developpeur.canadapost-postescanada.ca/devportal-portaildesdeveloppeurs/ship-parcels)
- Shipment notifications: `notification` element with `email` and `on-shipment`, `on-exception`, `on-delivery` flags, so Canada Post itself can email the customer tracking events. [F] - [Create Non-Contract Shipment](https://www.canadapost-postescanada.ca/info/mc/business/productsservices/developers/services/onestepshipping/createshipment.jsf)
- Neither the rating, non-contract shipment nor contract shipment documentation contains a dangerous goods or limited quantity field. [F] - the three pages above
- Coverage rules (Parcel Services guide, last updated Sept 7, 2026): Priority, Xpresspost and Expedited include up to $100; "You must buy the first $100 of liability coverage for Regular Parcel"; additional coverage in $100 increments up to $5,000; "purchase of the Signature option is mandatory when purchasing additional Liability Coverage of $200 or more" (Priority includes signature free). [F-PDF] - [Parcel Services shipping in Canada](https://origin-www.canadapost.ca/cpc/doc/en/support/parcel-services-shipping-in-canada.pdf); summary also at [Insurance coverage](https://www.canadapost-postescanada.ca/cpc/en/support/kb/claims/insurance-coverage.page)
- Proof of Age (18, 19 or 21) is available for a fee to SfSB cardholders and Standing Offer customers using Electronic Shipping Tools or Snap Ship; carrier checks ID when the receiver appears under 30. [F-PDF] - same guide
- Volumetric weight: "Cubic volume / density factor"; density factor 5,000 cm3/kg for Priority, Xpresspost, Expedited; 6,000 cm3/kg for Regular Parcel. Billable is the greater of actual and volumetric. [F-PDF, last updated Nov 10, 2025] - [ABCs of mailing](https://canadapost-postescanada.ca/cpc/doc/en/support/abcs-of-mailing.pdf)
- Oversize = any dimension over 1 m, or more than 76 cm on the second-longest side. Peak season Nov 2, 2026 to Jan 10, 2027: Oversize and Unpackaged surcharge $30 (from $21), Out-of-spec $400 (from $300); late-delivery guarantee claims honoured only if two or more business days late. [F-PDF] - [Parcel Services guide](https://origin-www.canadapost.ca/cpc/doc/en/support/parcel-services-shipping-in-canada.pdf), [Peak season 2026 notice, posted Sept 2, 2026](https://www.canadapost-postescanada.ca/cpc/doc/en/business/customer-notice-peak-season2026-e.pdf)
- Dangerous goods: generally non-mailable; "expanded acceptance program" for limited quantities, excepted quantities and lithium batteries exists for contract customers and SfSB cardholders; details only via sales rep or 1-888-550-6333. Perfume is listed under flammable liquids. [F; F-PDF last updated May 29, 2026] - [Dangerous goods overview](https://www.canadapost-postescanada.ca/cpc/en/support/articles/non-mailable-matter/dangerous-goods-overview.page), [Non-mailable matter PDF](https://www.canadapost-postescanada.ca/cpc/doc/en/support/non-mailable-matter.pdf)
- Qualifying limited or excepted quantities "can only be shipped within Canada by ground using Regular Parcel or Expedited Parcel". [S, from an older Canada Post guide section; not re-read in a current document] - [Section 6, ABCs of shipping](https://prd10.wsl.canadapost.ca/cpc/doc/en/support/customer-guide/section_6_the_abcs_of_shipping.pdf)
- TDG Regulations s.1.17 (version 2026-07-01 to 2026-10-19, archived page): applies to dangerous goods other than explosives; outer package gross mass "less than or equal to 30 kg"; each inner container at or under the Schedule 1 column 6(a) figure; then Parts 3 to 8 and 17 (documents, labels, placards, training) do not apply provided the limited quantity mark is on one side: a square on point, top and bottom black, centre white, sides at least 100 mm (50 mm minimum on small packages). [F] - [Justice Laws s.1.17](https://www.laws-lois.justice.gc.ca/eng/regulations/SOR-2001-286/section-1.17-20260701.html)
- UN1266 perfumery products, Packing Group II: limited quantity figure reported as 5 L per inner container. [3RD, S] - [ICC Compliance Center](https://www.thecompliancecenter.com/a-guide-to-shipping-cosmetics-for-the-untrained-consumer/)

### Inferences
- "Always correct" means sending real packed-box dimensions, not just weight: the response's cubed weight and the oversize flag are driven by them. Send only the option codes the order will really ship with (COV with amount, SO when coverage is $200+), and display `due` minus taxes or `due`, never a recomputed sum.
- Correction to docs/SHIPPING.md: the current guide makes Signature mandatory with additional coverage of $200 or more (not at $100), and Regular Parcel includes no coverage at all. The live call prices this itself if COV and SO are sent.
- Regular Parcel uses divisor 6,000 versus 5,000 for Expedited. For a light, bulky hookah box Regular Parcel can bill a lower weight than Expedited, so "Regular is never offered because the price is the same" holds only for the same billable weight; rate both and compare.
- Cologne: the store must hard-filter services to DOM.RP and DOM.EP for any cart containing a flagged item, block air-stage destinations, apply the limited quantity mark at packing, and get the acceptance-program terms in writing from Canada Post first. The API will not stop a wrong choice.
- From Nov 2, 2026 to Jan 10, 2027 an oversize hookah box costs $9 more than the local table assumes if the table holds the $21 figure.

### Gaps
- Canada Post's own written conditions for the limited quantity acceptance program (services, marks, air stage exclusions, registration): COULD NOT VERIFY in a current document. Confirm by calling 1-888-550-6333 and asking for the terms in writing.
- Schedule 1 column 6(a) value for UN1266 PG II and the cologne's actual UN number and packing group: confirm against the supplier SDS and the Schedule 1 text on Justice Laws.
- Whether the new JSON Rating API returns the same field set under new names: stated only as "complete feature parity"; confirm in the signed-in reference.
- Delivery Confirmation code DC appears in the new portal list and a legacy sample but not in the legacy valid-values list; confirm before sending.

## 4. Reliability, strikes, and a second carrier

### Takeaway
Canada Post publishes no uptime figure, takes its web services down every Saturday 9 pm to Sunday 7 am ET for maintenance, and went through a 32-day national strike in late 2024 and national then rotating strikes in autumn 2025; the labour dispute is now closed with agreements running to January 31, 2029. A second carrier is still sensible insurance, and the cleanest route for a custom store is an aggregator API or a direct Purolator account.

### Cited Findings (all read 2026-11-14)
- Scheduled maintenance: every weekend "from Saturday at 9 pm to Sunday at 7 am ET", some features may be unavailable; plus monthly two-day planned outage windows in 2026 (Jan 17-18, Feb 21-22, Mar 21-22, Apr 18-19, May 16-17, Jun 20-21, Jul 18-19, Aug 17-18, Sep 19-20, Oct 17-18). No uptime target, status page or incident history published. Unscheduled outages are announced by email. [F] - [Service availability](https://developer-developpeur.canadapost-postescanada.ca/devportal-portaildesdeveloppeurs/service-availability)
- No warranty of uninterrupted service; services may be removed without notice. [F] - [Developer Portal Agreement](https://www.canadapost-postescanada.ca/cpc/en/support/kb/company-policies/terms-conditions/developer-portal-terms-and-conditions.page)
- Legacy retry guidance only: HTTP 202 wait about one second before Get Artifact; 404 retry later if just created; 412 "repeat the transaction after a short time". Forum shows HTTP 504 and error 8511 reports in July-August 2026. [F] - [REST fundamentals](https://www.canadapost-postescanada.ca/info/mc/business/productsservices/developers/services/fundamentals.jsf), [forum category](https://forum.developer-developpeur.canadapost-postescanada.ca/c/test-category/14)
- Strike history: national strike began Nov 15, 2024 and ended mid-December 2024 (CIRB back-to-work order; sources give Dec 15 and Dec 17); overtime ban from May 23, 2025; national strike resumed Sept 25, 2025; switched to rotating strikes Oct 10, 2025; suspended Nov 21, 2025 on tentative agreements. [3RD] - [Wikipedia: 2024-2025 Canada Post labour dispute](https://en.wikipedia.org/wiki/2024%E2%80%932025_Canada_Post_labour_dispute)

## 6. Packing and fulfilment workflow for one or two staff

### Takeaway
The carrier pieces exist for a simple loop: paid order, pick list, pack into the box that was quoted, buy the label (4x6 PDF), Canada Post emails tracking, drop off or book a $3.50 pickup. Glass needs cushioning on all sides and, for box-in-box, an outer box about 15 cm larger in every dimension, which is what drives volumetric weight and therefore price.

- Split orders: quote per box at checkout (sum of each box's rate), buy one label per box, store an array of tracking numbers on the order.

## 7. Box logic

### Takeaway
No library offers proven carton-fit accuracy; the dependable approach is a short list of stocked box sizes, a per-product "ships in its own box" profile for hookahs and glass, and bin-packing only for the loose small items, with the chosen box saved on the order so the packer uses the same one.

### Cited Findings (all read 2026-11-14)
- JavaScript/TypeScript packing libraries: `binpackingjs` (2D and 3D, 3D ported from Go bp3d, pivot-based placement); `boxpacker-js` (TypeScript port of PHP BoxPacker, respects box max weight, rotation policies BestFit/KeepFlat/Never, very low download count); `binpack3d` (port of py3dbp with weight limits, fragile items, stability checks); `@0xdoublesharp/bin-packing-wasm` (Rust/WASM, states it runs on Cloudflare Workers). None publish real-world carton-fit benchmarks. [S, npm listings] - [binpackingjs](https://www.npmjs.com/package/binpackingjs), [boxpacker-js stats](https://www.pkgstats.com/pkg:boxpacker-js), [binpack3d](https://socket.dev/npm/package/binpack3d)
- Canada Post bills each box on the greater of actual and volumetric weight, and applies a cubing adjustment when declared dimensions differ from those detected. [F-PDF; F in SHIPPING.md] - [ABCs of mailing](https://canadapost-postescanada.ca/cpc/doc/en/support/abcs-of-mailing.pdf)
- Shippo and EasyPost sell cartonization only through sales contact (docs/SHIPPING.md).

### Inferences
- Rule set that keeps quote and reality aligned: (a) every hookah and every glass SKU carries a fixed packed-box profile (outer L/W/H, packed weight) and ships alone or with a named list of small add-ons that fit its void space; (b) remaining small items go through a simple packer against 4 to 6 stocked boxes with a fill-factor cap (for example 70 to 80 percent of volume, to leave room for cushioning); (c) the order stores the box plan and the pick list prints it, so the packer is told "Box B, 40 x 30 x 20"; (d) if the packer changes the box, the admin re-rates before buying the label and shows the difference.
- Geometric packers assume rigid cuboids and no cushioning, so they under-size boxes for fragile goods. The fill-factor cap and per-item padding allowance matter more than which library is used. The fill-factor range is a working assumption, not a sourced figure; tune it from the first 50 real packs.
- The mockup's existing packer already splits parcels over 30 kg; the same code can run in the Worker since these libraries are plain JS.

### Gaps
- No measured accuracy data for any open-source packer in e-commerce use was found.
- No sourced industry figure for a fill-factor cap.

## 8. Pickup orders

### Takeaway
The proven pattern is three messages (confirmed, ready, reminder), a stated hold period of about 7 days, and a release-and-refund rule for unclaimed orders; ID checking rules should match the product, which for age-restricted goods means photo ID at handover.

### Cited Findings (all read 2026-11-14)
- Shopify's local pickup flow: per-location pickup instructions, an expected pickup time shown at checkout, staff mark the order ready which sends a "Ready for pickup" email (resendable), then "Mark as picked up" fulfils the order and can send a confirmation. Shopify's page gives no ID or unclaimed-order policy. [F] - [Shopify local pickup](https://help.shopify.com/en/manual/fulfillment/setup/delivery-methods/pickup-in-store)
- Hold periods in practice: commonly about 7 days from the ready notice with automatic stock release; Best Buy's published policy was a five-day hold; a small boutique uses 14 days (7 for discounted orders) and cancels with refund or store credit. [3RD] - [HotWax](https://www.hotwax.co/blog/the-cost-of-forgotten-orders-managing-failed-pickups-in-retail), [Digital Commerce 360](https://www.digitalcommerce360.com/2021/12/17/the-shopper-speaks-so-many-reasons-to-say-ill-pick-it-up-curbside/), [The Knitting Loft](https://theknittingloft.ca/pages/picking-up)
- Recommended messages: at order confirmation, at ready-for-pickup, and a reminder before the window closes; expiry notices should be a separate message. [3RD] - [Racklify](https://racklify.com/encyclopedia/how-to-implement-pickup-in-store-a-practical-checklist-for-stores/), [Sequenzy](https://www.sequenzy.com/blog/local-pickup-ready-email-template)
- Ontario requires online retailers of tobacco and vapour products to verify the buyer is at least 19 (recorded in docs/SHIPPING.md); this store does not ship those, but the same handover check applies to any age-restricted item sold for pickup.

### Inferences
- Minimum build: order status "ready" triggers an email with the order code, hours, address and hold-until date; the counter screen looks up the code; staff tick "ID checked" when the order contains a flagged item; a reminder goes two days before expiry; at expiry the order moves to an "unclaimed" list for a manual refund decision (refunds are the owner's call, not automatic).
- Showing the pickup code as a QR in the email lets the same phone-camera scanner used for packing confirm handover.

### Gaps
- No authoritative Canadian standard for pickup ID checks on non-regulated goods was found; sources are vendor blogs.
- Refund timing rules for unclaimed prepaid orders under Ontario consumer law: not researched.

## 9. Tracking and delivery problems

### Takeaway
Canada Post tracking is poll-only (no webhooks) and the legacy tracking limit is just 20 calls a minute by default, so rely on Canada Post's own notification emails plus a slow background poll. Claims must be opened by the sender within 90 days; coverage pays the lowest of item value, coverage bought or included coverage, and multiple reports say glass and other fragile items are not covered for damage.

### Cited Findings (all read 2026-11-14)
- Tracking API 2.0.0 operations: Get Tracking Summary (by PIN, DNC or reference), Get Tracking Details (all events), Get Delivery Confirmation Certificate (PDF with signatory and signature image if available). No webhook, push or subscription is documented. [F] - [Tracking overview](https://developer-developpeur.canadapost-postescanada.ca/devportal-portaildesdeveloppeurs/api/overview/tracking)
